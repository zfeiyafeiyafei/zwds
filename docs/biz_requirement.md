# 紫微斗数智能分析平台需求文档（V3：融合专家建议与实施路线）

## 1. 修订说明

在原有需求基础上，新增一项非常重要的产品能力：

> **命盘展示主题系统（Chart Theme & Layout System）**

传统紫微斗数软件多数采用九宫格或十二宫格布局，但从产品设计和用户体验角度来看，命盘展示方式不应被固定为单一版式。系统应支持多种命盘主题与可切换布局，以满足不同用户群体、不同审美风格和不同使用场景的需求。

因此，本次修订重点补充以下能力：

1. 支持多种命盘展示主题

2. 支持不同宫位布局方式

3. 支持统一的主题配置模型

4. 支持桌面端、Web端、移动端的统一渲染规范

5. 支持未来扩展更多视觉风格和交互样式


## 1.1 V3 修订说明（专家建议融合）

在 V2（命盘主题与布局系统）基础上，本次修订融合紫微斗数软件专家建议，新增以下能力：

1. 流月 / 流日周期推演（§4.1.5）

2. 排盘图片导出与分享（§4.2.3）

3. 格局库扩充要求，明确凶格覆盖（§4.3.1）

4. 主星双星组合解释库完整化（§4.3.2）

5. 合盘分析功能（§4.5）

6. 三方四正联动高亮与运限四化叠加显示（§5.8）

7. 实施路线规划（§10）

另有部分条目（农历输入、闰月标记、出生地点/时区/真太阳时、杀破狼/机月同梁/阳梁昌禄等格局、双星组合分析）在 V2 中已列为需求但尚未实现，属于实现缺口而非需求缺口，优先级见 §10。

# 2. 产品定位（修订版）

本产品定位为：

> **一个以紫微斗数计算引擎为核心、以结构化命盘数据为基础、支持多种命盘展示主题、规则分析和 AI 解读的跨平台智能命理分析平台。**

它不仅要“算得对”，还要“看得清、看得美、看得懂”。

因此产品包含三层价值：

1. **计算层**：负责排盘与周期推演

2. **分析层**：负责格局、星曜、大限、流年、小限解析

3. **展示层**：负责以多种主题与布局方式清晰呈现命盘

# 4. 核心功能需求

## 4.1 排盘功能

系统必须支持以下排盘能力：

### 4.1.1 本命盘

根据用户出生信息生成本命盘。

输入信息包括：

- 姓名（可选）

- 性别

- 阳历生日 / 农历生日

- 出生时间

- 出生地点（可选，供未来时区与真太阳时扩展）

- 时区（可选）

- 闰月标记（农历时适用）

输出内容包括：

- 十二宫

- 宫位地支

- 宫位天干

- 主星

- 辅星

- 杂曜 / 煞曜

- 四化

- 长生十二神（可选）

- 其他扩展神煞（可配置）

---

### 4.1.2 大限盘

系统应支持生成与展示大限信息，包括：

- 起限年龄

- 顺逆行规则

- 每十年大限的对应宫位

- 大限宫星曜分布

- 大限分析结果

默认情况下，当用户未指定分析年龄时，系统应基于当前系统时间自动定位当前大限。

---

### 4.1.3 流年盘

系统应支持生成与展示流年信息，包括：

- 当前年份流年

- 用户指定年份流年

- 流年对应宫位与星曜信息

- 流年四化与对应分析

默认年份应取系统当前年份。

---

### 4.1.4 小限盘

系统应支持生成与展示小限信息，包括：

- 当前年龄对应小限

- 用户指定年龄的小限

- 小限落宫信息

- 小限与本命、大限、流年的叠加分析

默认情况下，应根据系统当前日期自动计算用户当前年龄对应的小限。

### 4.1.5 流月 / 流日盘（V3 新增）

在流年基础上进一步支持更细粒度周期：

- 当前流月 / 用户指定流月的落宫与四化

- 当前流日 / 用户指定流日的落宫

- 流月、流日与本命、大限、流年的叠加定位

默认取系统当前日期。引擎周期框架应保证大限 → 流年 → 流月 → 流日的规则可逐级扩展，而非各自硬编码。

---

## 4.2 命盘数据保存与读取

### 4.2.1 JSON 保存

系统必须支持将完整排盘结果保存为 JSON 文件，并支持后续重新打开使用。

目标：

- 排盘数据可持久化

- 排盘结果可跨平台复用

- 可作为 AI 分析输入

- 可作为同步与备份基础格式

保存内容包括：

- 出生资料

- 排盘参数

- 命盘结构

- 时间周期数据

- 分析结果

- 主题配置（可选）

- 版本信息

---

### 4.2.2 JSON 打开与恢复

系统必须支持：

- 从本地 JSON 文件打开命盘

- 恢复命盘全部结构

- 恢复排盘展示方式

- 恢复已保存的分析结果

- 恢复主题选择和布局配置（如果存在）

### 4.2.3 排盘图片导出（V3 新增）

系统应支持将命盘展示结果导出为图片，用于分享与报告配图：

- 导出格式：PNG（位图）与 SVG（矢量）

- 导出内容跟随当前主题与布局（宫格 / 圆形 / 环形均适用）

- 导出范围可选：仅命盘，或命盘 + 当前分析摘要

- 移动端与 Web 端用于分享场景，桌面端用于报告与打印

该能力与主题系统（§5）联动：图片渲染必须复用同一套主题配置，保证所见即所得。

---

## 4.3 命盘解析功能

系统需支持结构化解析，而不仅仅是显示排盘结果。

### 4.3.1 格局分析

自动识别命盘格局，例如：

- 紫府朝垣

- 杀破狼

- 机月同梁

- 阳梁昌禄

- 君臣庆会

- 其他可扩展格局

- 凶格同样必须覆盖，例如：

  - 羊陀夹忌

  - 火铃夹命

  - 马落空亡

  - 梁马飘荡

- 格局数量应随知识库持续扩充，新增格局不得改动引擎核心代码

每个格局分析应至少输出：

- 格局名称

- 成立条件

- 命盘中的证据

- 强弱等级

- 主要影响领域

- 简要解释

---

### 4.3.2 星曜分析

应支持以下层次的星曜分析：

1. 单星分析

2. 双星组合分析

3. 多星组合分析

4. 星曜落宫分析

5. 星曜与四化联动分析

其中双星组合分析要求建立**完整的主星双星组合解释库**（紫微天府、紫微贪狼、廉贞七杀、武曲破军等共 60 种组合），每个组合至少输出：

- 组合特质与相互作用

- 优势与风险

- 在各宫位的典型表现差异

输出内容示例：

- 星曜含义

- 性格倾向

- 优势与风险

- 在当前宫位的表现

- 在本命 / 大限 / 流年 / 小限中的作用

---

### 4.3.3 周期分析

系统必须支持：

- 大限分析

- 流年分析

- 小限分析

- 三者叠加分析

分析维度建议包括：

- 总体趋势

- 性情发展

- 学业

- 事业

- 财富

- 婚姻

- 健康

- 人际关系

- 家庭关系

---

## 4.4 AI 提示词与智能分析功能（V3.1 细化）

### 4.4.1 配置入口

排盘界面提供**设置按钮**，打开 AI 配置对话框，包含两个区域：

1. **LLM API 配置**：用户自定义 AI 分析引擎
   
   - Base URL（默认 `https://api.openai.com/v1`）
   
   - API Key（仅本地存储，列表/读取接口脱敏返回）
   
   - 模型名称（如 `gpt-4o-mini`、`deepseek-chat`、`qwen-plus`）
   
   - 任何兼容 OpenAI Chat Completions 协议的服务均可接入（OpenAI、Claude 兼容网关、DeepSeek、通义、本地 Ollama / vLLM 等）

2. **Skill 管理**：内置 skill 列表 + 用户自定义 skill 的新增 / 编辑 / 删除
   
   - 内置 skill 只读：不可删除、不可改名、内容随引擎版本刷新；需要调整时复制内容新建自定义 skill
   
   - 自定义 skill 完全可编辑

### 4.4.2 Skill（提示词）体系

Skill 本质是一段提示词模板。系统内置以下 skill：

| 内置 Skill | 分析焦点 |
| --- | --- |
| 总体分析 | 命盘整体概览：命身格局、三方四正、核心优势与人生基调 |
| 性情分析 | 性格特质、思维模式、情绪倾向、人际风格 |
| 事业分析 | 职业方向、官禄宫与命宫联动、适合的行业与发展节奏 |
| 财富分析 | 财帛宫、理财风格、求财方式与风险 |
| 感情分析 | 夫妻宫、感情模式、婚恋倾向与相处建议 |
| 健康分析 | 疾厄宫、体质倾向、需注意的健康领域 |
| 学业分析 | 学习能力、考试运、适合的学科方向 |
| 流年运势 | 当前大限 / 流年 / 小限的趋势解读 |

每个 skill 字段：

- 名称（唯一）

- 分类（内置 / 自定义）

- 提示词内容

- 创建 / 更新时间

**命盘数据自动附加规则（核心约束）**：

- 调用任一 skill 时，系统自动将**当前命盘的完整 JSON**（排盘结构 + 格局分析 + 星曜分析 + 运限定位）附加到对话上下文中

- 附加方式：skill 提示词作为 system 消息，命盘 JSON 以独立消息随附，用户无需手工粘贴

- 内置 skill 的提示词文本中不含命盘数据占位符，数据由系统统一注入，保证所有 skill 行为一致

### 4.4.3 AI 分析页签

排盘界面顶部提供页签菜单：**排盘 / AI 分析**。

AI 分析页签为**对话式界面**：

1. **Skill 选择器**：下拉列出全部内置 skill 与用户自定义 skill；选中即发起一次分析（system = skill 提示词，user = 命盘 JSON + 默认引导语）

2. **对话区**：
   
   - 分析结果以对话气泡呈现
   
   - **必须流式输出**：LLM 逐 token 返回，界面实时增量渲染，不允许等待完整响应后一次性显示
   
   - 渲染中显示"生成中"状态，支持中途停止

3. **追问输入框**：用户可在分析结果后继续追问，对话历史（含命盘 JSON 上下文）随请求一并发送，保证多轮一致性

4. **命盘联动**：切换当前命盘时，提示用户对话上下文基于旧盘，可一键以新盘重新开始

### 4.4.4 LLM API 扩展能力

处理流程：

```id="0m2qkg"
Skill 提示词（system）
   +
命盘 JSON（自动附加）
   +
规则分析结果（含于命盘 JSON）
   ↓
LLM（OpenAI 兼容协议，流式）
   ↓
流式自然语言分析
```

原则：

- **排盘和规则判断由系统完成**

- **LLM 负责解释、润色和扩展表达**

- **不能把核心命理规则完全交给 LLM 推断**

- 后端作为 LLM 代理转发（SSE 流式中继），API Key 不经过前端直连，避免 webview / 浏览器端泄露与跨域问题

## 4.5 合盘分析功能（V3 新增）

系统应支持两张命盘的对比分析，用于夫妻、亲子、合伙等关系场景：

- 双盘并排 / 叠加展示

- 宫位互参：甲方星曜落入乙方宫位的影响（如甲夫妻宫主星与乙命宫的关系）

- 四化互飞：一方生年四化落入另一方命盘的宫位解读

- 关系维度摘要：性格契合、价值观、相处模式、潜在冲突点

限制：

- 合盘规则判断由规则引擎完成，LLM 仅负责表达（同 §4.4.3 原则）

- 合盘结果应可随任一命盘 JSON 一起导出

# 5. 新增重点模块：命盘展示与主题系统

这是本次修订的重点内容。

## 5.1 设计目标

命盘展示系统应满足以下目标：

1. 支持多种视觉主题

2. 支持多种宫位布局

3. 同一命盘数据可切换不同表现形式

4. 布局与数据解耦

5. 兼顾专业用户与普通用户的阅读习惯

6. 兼顾桌面、Web、移动端显示效果

---

## 5.2 主题系统的基本要求

系统应至少支持以下主题概念：

- **传统主题**：接近经典九宫格 / 十二宫格展示

- **简洁主题**：强调信息密度与清晰阅读

- **现代主题**：更适合大众用户和移动端

- **图形主题**：强调视觉化、适合展示和分享

每个主题可定义：

- 背景样式

- 文字字体

- 宫位边框样式

- 颜色体系

- 星曜显示方式

- 四化显示方式

- 高亮规则

- 交互效果

---

## 5.3 布局系统要求

系统不能只支持单一九宫格布局，而应至少支持以下布局类型。

### 5.3.1 传统宫格布局

即传统斗数软件常见的九宫格 / 外围宫格布局。

特点：

- 便于专业用户阅读

- 符合传统习惯

- 适合分析型界面

适用场景：

- 专业排盘

- 桌面端

- 深度研究

---

### 5.3.2 圆形均匀布局（新增重点）

这是你提出的非常重要的需求。

系统应支持：

> **以大小一致、排列均匀的圆圈来展示十二宫**

具体要求：

- 十二宫以圆形节点展示

- 每个宫位节点大小一致

- 节点沿圆周或规则路径均匀排列

- 宫位之间保持视觉平衡

- 中央区域可放置命盘摘要、命主信息或当前分析主题

- 星曜信息可显示在圆圈内部或展开层中

展示形式示意：

```id="1t03bs"
          [父母]
    [福德]      [命宫]

 [田宅]            [兄弟]

 [官禄]            [夫妻]

 [仆役]            [子女]

    [迁移]      [财帛]
          [疾厄]
```

也可以设计为完整 12 等分环形结构。

特点：

- 更现代

- 更美观

- 更适合展示

- 更适合移动端与分享场景

- 用户更容易感知十二宫之间的整体关系

适用场景：

- 大众用户界面

- 移动端

- Web 展示页

- AI 报告配图

- 截图分享

---

### 5.3.3 环形/轨道式布局（可扩展）

在圆形均匀布局基础上，未来可以进一步支持：

- 内环：命盘主体

- 外环：大限

- 再外环：流年 / 小限

- 高亮当前年龄对应宫位

适合时间周期的可视化展示。

---

## 5.4 布局与数据分离原则

系统必须做到：

> **同一份命盘 JSON 数据，可以使用不同布局渲染。**

因此命盘数据不应写死布局坐标。

错误设计：

```id="w7wfxh"
命宫 x=10 y=20
财帛宫 x=50 y=80
```

正确设计应为：

```id="sxtsj8"
palace: 命宫
order: 1
branch: 子
stars: [...]
```

布局引擎根据主题动态计算位置。

---

## 5.5 主题配置项

建议设计统一主题配置结构，至少包括：

- theme_id

- theme_name

- layout_type

- color_palette

- font_family

- font_size

- palace_shape

- palace_border_style

- star_display_style

- line_style

- highlight_style

- background_style

- animation_style

例如：

```json
{
  "theme_id": "circular_modern",
  "theme_name": "现代圆形主题",
  "layout_type": "circular_equal_nodes",
  "palace_shape": "circle",
  "color_palette": "light_gold",
  "star_display_style": "compact",
  "highlight_style": "current_period"
}
```

---

## 5.6 主题切换功能

系统应支持：

- 同一命盘一键切换主题

- 切换后数据不变，仅展示方式变化

- 记忆用户偏好主题

- 主题切换后立即重绘命盘

- 保存主题选择到本地配置或命盘文件中

---

## 5.7 不同平台下的表现要求

### 桌面端

重点：

- 信息完整

- 可同时显示命盘与分析结果

- 适合复杂布局

- 适合圆形 / 宫格式切换

---

### Web 端

重点：

- 美观

- 响应式布局

- 适配大屏和普通浏览器窗口

- 支持分享展示

---

### 移动端

重点：

- 重点信息突出

- 圆形布局优先

- 可手势缩放

- 可点击宫位查看详情

- 支持分层显示，避免信息过密

---

## 5.8 交互要求

命盘展示不仅是静态图，还应支持交互。

建议支持：

- 点击宫位查看详情

- 点击星曜查看解释

- 高亮当前大限宫

- 高亮当前流年宫

- 高亮当前小限宫

- 切换分析维度时同步高亮相关宫位

- 点击宫位时联动高亮三方四正（本宫、对宫及财帛、官禄三合线）

- 支持在命盘上叠加显示大限四化与流年四化的落宫标记（可开关）

- 支持鼠标悬停（桌面 / Web）

- 支持手势缩放与拖动（移动端）

# 6. 数据模型补充要求

为支持主题系统，命盘 JSON 结构建议新增展示配置区域。

例如：

```json
{
  "chart": { "...": "..." },
  "analysis": { "...": "..." },
  "display": {
    "default_theme": "traditional_grid",
    "available_themes": [
      "traditional_grid",
      "circular_equal_nodes",
      "modern_clean"
    ],
    "current_layout": "circular_equal_nodes"
  }
}
```

注意：

- 这里存储的是“主题选择与偏好”

- 不是写死坐标数据

- 坐标应由前端布局引擎运行时生成

# 7. 非功能需求补充

## 7.1 可扩展性

命盘展示系统应支持后续继续添加：

- 新主题

- 新布局

- 新图标风格

- 新高亮模式

- 新动画方式

无需修改核心排盘算法。

---

## 7.2 一致性

同一主题在 Linux / Windows / macOS / Web / Mobile 中应尽可能保持一致的视觉规则和信息结构。

---

## 7.3 性能

在切换主题、切换年份、切换分析维度时，应保证：

- 响应流畅

- 命盘重绘时间可接受

- 大多数场景下不出现明显卡顿

# 8. 修订后的需求重点总结

在你原有的四项核心需求基础上，系统需求现在应升级为五大核心能力：

1. **排盘能力**
   
   - 本命
   
   - 大限
   
   - 流年
   
   - 小限

2. **数据保存能力**
   
   - JSON 保存
   
   - JSON 读取
   
   - 跨端可复用

3. **命盘解析能力**
   
   - 格局分析
   
   - 星曜分析
   
   - 周期分析

4. **AI 分析能力**
   
   - 多套常用 Prompt
   
   - LLM API 扩展
   
   - 规则分析 + LLM 表达

5. **命盘展示主题能力（新增重点）**

   - 圆形均匀节点主题
   
   - 多主题切换
   
   - 布局与数据分离

6. **合盘分析能力（V3 新增）**
   
   - 双盘对比展示
   
   - 宫位互参与四化互飞
   
   - 关系维度摘要

# 9. 最终建议

这个补充非常关键，而且我认为应该上升为**一级功能模块**，不能只当作“UI美化”。

因为它实际决定了：

- 产品的视觉差异化

- 用户的第一印象

- 移动端可用性

- 分享传播能力

- 后续高级图形化分析能力

所以建议正式将它命名为：

> **命盘展示与主题系统（Chart Presentation & Theme System）**

并作为产品核心能力之一，与“排盘引擎”“分析引擎”“AI分析系统”并列。

主题系统的地位已由 V2 确立。V3 在此之上融合专家建议，补齐周期细度（流月/流日）、解析深度（双星组合库、凶格、运限四化上盘）、传播能力（图片导出）与场景扩展（合盘），并给出三期实施路线（§10）。本文档可作为直接进入设计阶段的正式版本。

# 10. 实施路线（V3 新增）

依据当前实现状态（2026-09），需求按投入产出分三期推进。

## 10.1 近期：解析层收口

目标：把"排得对"升级为"解得全"，不接 LLM 即可产出完整解读。

1. 农历输入 + 闰月标记（V2 已列需求，补前端入口；引擎已有转换能力）

2. 早晚子时规则开关（流派分歧点，作为规则包体系第一个可配置项）

3. 主星双星组合解释库（§4.3.2）

4. 补齐文档点名格局：杀破狼、机月同梁、阳梁昌禄、紫府朝垣及凶格（§4.3.1）

5. 大限 / 流年四化叠加显示（§5.8；引擎已算出运限四化，仅差 UI 叠加层）

6. 三方四正联动高亮（§5.8；前端已有宫位关系叠加层基础）

7. 周期解读文本：大限 / 流年 / 小限的总体趋势与事业、财富、婚姻、健康维度分析（§4.3.3）

## 10.2 中期：差异化能力

目标：建立产品与传播壁垒。

1. 统一主题配置模型抽象（§5.5；现有明暗主题为第一个 palette 实例）

2. 环形 / 轨道式布局：内环本命、外环大限流年（§5.3.3）

3. 排盘图片导出 PNG / SVG（§4.2.3）

4. 主题 / 布局偏好存入命盘 JSON 的 display 区（§6）

5. 合盘分析（§4.5）

6. Prompt 模板系统落地：模板 CRUD + 命盘 JSON 组装导出，暂不接 LLM（§4.4.1 / §4.4.2）

## 10.3 远期：平台化

目标：多平台与商业化扩展。

1. LLM API 接入与 AI 报告（§4.4.3；架构文档 §9）

2. 流派 / 规则包体系完整落地，支持同盘多流派解释（db 设计 A 域）

3. 出生地点、时区与真太阳时（§4.1.1 可选项）

4. 用户体系、PostgreSQL 云端与同步（架构文档 Phase 3）

5. Flutter 移动端与手势交互（架构文档 Phase 4、§5.7 移动端要求）
